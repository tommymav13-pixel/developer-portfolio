## Acquisition Strategy

Books should not be acquired simply to expand the collection.

A book should preferably satisfy at least one of the following:

1. It supports the current learning phase.
2. It fills a clear knowledge gap.
3. It will be used within the foreseeable future.
4. It is an important long-term technical reference.

Before acquiring a book:

1. Check `books/` to prevent duplicates.
2. Check whether another owned book already covers the topic.
3. Determine whether the book belongs to the current learning phase.
4. Add it to this file if it is worth acquiring later.

## File Naming After Acquisition

Books should follow the library naming convention:

`author_title_edition.ext`

Examples:

`brett_slatkin_effective_python_3e.pdf`

`andrew_hunt_david_thomas_the_pragmatic_programmer_20th_anniversary.pdf`

`brian_ward_how_linux_works_3e.pdf`

`marc_deisenroth_aldo_faisal_cheng_soon_ong_mathematics_for_machine_learning.pdf`

The existing library naming conventions in the Developer Handbook
remain authoritative.
