## Acquisition Strategy

Books should not be acquired simply to expand the collection.

A new book should preferably satisfy at least one of the following
conditions:

1. It directly supports the current learning phase.
2. It fills a clearly identified knowledge gap.
3. It will be actively used within the foreseeable future.
4. It provides substantially better coverage than books already owned.
5. It is likely to remain useful as a long-term technical reference.

Before acquiring a book:

1. Check the existing library to prevent duplicates.
2. Determine whether an owned book already covers the subject adequately.
3. Check the current learning roadmap and curriculum.
4. Determine whether the prerequisite knowledge is already present.
5. Prefer books that support practical exercises or projects.
6. Add the book to this file if acquisition is justified.

## Relationship to the Reading List

This file answers:

The separate `reading_list.md` answers:

> Which books are relevant to my learning path, and when should I study them?

Ownership and reading priority are therefore treated separately.

A book can be:

- owned but not currently relevant;
- owned and actively studied;
- not owned but worth acquiring;
- planned for a much later learning phase.

## File Naming After Acquisition

Books should follow the library naming convention:

```text

```

Examples:

